# Mock Testing Suite Tutorial Script

Audience: MTS testers and evaluators preparing for certification mock sessions.

Estimated runtime: 12-15 minutes.

## Scene 1 - Setup

Narration: "Start in Setup or Settings and confirm your tester name, form link, spreadsheet link, browser behavior, sound, ticker speed, and optional Gemini settings."

Screen actions: Open Settings, review General, Payment Settings, Gemini AI, Calendar, Discord Posts, and Help.

Callouts: Settings changes affect future sessions. Help content and notification rows are managed separately from normal tester settings.

Troubleshooting notes: If a link or key test fails, verify the saved value and retry. Do not paste credentials into chat or screenshots.

## Scene 2 - Basics

Narration: "Basics verifies the candidate, final-attempt risk, headset, VPN, and browser readiness before scoring begins."

Screen actions: Enter a candidate name, wait for shared lookup, review prior sessions when shown, confirm Final Attempt, and complete readiness checks.

Callouts: Candidate lookup waits for a stronger name. Shared data outages should not stop local session work.

Troubleshooting notes: If shared lookup is unavailable, continue in local session mode and retry later.

## Scene 3 - Headset Lookup and Research

Narration: "Search approved headsets by brand or model. If the model is not listed, research it before deciding whether the session can continue."

Screen actions: Open Approved Headset Lookup, search a model, select an approved result, then demonstrate an unknown model showing Headset not found.

Callouts: Research Headset is the recommended next step. Use This Headset For Now does not approve or add the headset.

Troubleshooting notes: Confirm USB and noise-cancelling microphone support before allowing an unlisted headset. Administrator review is still required.

## Scene 4 - VPN Verification

Narration: "VPN and proxy checks are decision support. Manual lookup is the release-safe default, and integrated checks are optional when provider keys are configured."

Screen actions: Expand VPN & Proxy Verification, copy the candidate IP, open manual lookup links, and show integrated mode messaging when available.

Callouts: The tester always makes the final decision. One provider cannot produce a confident clear result.

Troubleshooting notes: If providers are unavailable, use manual lookup and wait a few minutes after the candidate disables VPN before rechecking.

## Scene 5 - Calls

Narration: "Calls records call type, show, caller, payment simulation, coaching, and fail reasons."

Screen actions: Complete one passing call and one failing call example, including coaching and fail reason details.

Callouts: Payment dropdowns start on Default for each new call. Coaching selections feed Review summaries.

Troubleshooting notes: Use Tech Issue for routing, browser, Discord, or internet problems instead of forcing a scoring decision.

## Scene 6 - Supervisor Transfers

Narration: "Supervisor Transfer verifies transfer handling after the mock call requirement is met."

Screen actions: Show transfer reason, caller, show, payment option, pass/fail buttons, coaching, and fail reason copy behavior.

Callouts: Supervisor Transfer Only resumes candidates who already completed mock calls.

Troubleshooting notes: If the candidate cannot complete the transfer today and it is not final attempt, route to Newbie Shift when prompted.

## Scene 7 - Tech Issues

Narration: "Tech Issue guides internet speed, call routing, no script pop, Discord, and Other technical issues."

Screen actions: Open Tech Issue, run the speed workflow, show the passed-speed question for other issues, enter Other Technical Issue text, and answer session completion.

Callouts: Other notes populate the Other field during form fill. Unresolved issues preserve the session data for Review or Newbie Shift.

Troubleshooting notes: If speed is below threshold, route to Review. If speed passes but another issue remains, document it before deciding completion.

## Scene 8 - Review

Narration: "Review is the final checkpoint before filling the certification form or saving the session."

Screen actions: Review basics, call results, supervisor transfer results, coaching summary, fail summary, final readiness judgment, Fill Form, and Save and Finish.

Callouts: Edit summaries before form fill when needed. Save and Finish updates local history and shared tracking when available.

Troubleshooting notes: If shared updates fail, local save still completes. Retry shared sync later.

## Scene 9 - History

Narration: "History stores recent local sessions and supports read-only review or historical form fill."

Screen actions: Open History, select a session, review details, and show historical fill form.

Callouts: Local History is separate from SAM shared candidate history.

Troubleshooting notes: Clearing local History does not delete SAM admin records.

## Scene 10 - Help

Narration: "Help explains each major feature and includes FAQ and tutorial replay."

Screen actions: Open Help, search or scan topics, replay tutorial, and review fallback behavior.

Callouts: Use Help during live sessions when a workflow decision is unclear.

Troubleshooting notes: If remote FAQ content fails, use the packaged fallback and try again later.

## Ending Checklist

- Tester identity and links are configured.
- Candidate readiness, headset, VPN, and browser checks are complete.
- Calls and supervisor transfers are scored with coaching/fail details.
- Tech issues are documented when they affect the session.
- Review summaries are checked before Fill Form.
- Session is saved, and shared sync is retried if temporarily unavailable.
